# BioMiner Benchmarking — XN Project (Assignment 1.2)

This repository benchmarks [BioMiner](https://github.com/jiaxianyan/BioMiner)
(Yan et al., 2026) - a multi-modal agentic framework for extracting
protein-ligand bioactivity data, including chemical structures, from
scientific PDFs - against the course's confirmed-ground-truth molecular
structure dataset, as part of the XN project's Phase 1 benchmarking.

This is a thin **wrapper and evaluation harness** around BioMiner. It does
not vendor, modify, or reimplement BioMiner itself; BioMiner must be
installed separately (instructions below) and this repo calls it as a
subprocess, then scores its output.

## What this code does

1. **Loads the dataset** (`src/data_loader.py`) - reads the ground-truth CSV
   (paper ID, molecule name, canonical SMILES) and matches each paper's
   entries to its corresponding PDF file.
2. **Runs BioMiner** (`src/biominer_runner.py`) - calls BioMiner's own
   `example_open_source.py` CLI on each PDF and parses the predicted SMILES
   out of BioMiner's result files.
3. **Scores the predictions** (`src/metrics.py`) - computes, per paper:
   - **Exact match** precision / recall / F1, using RDKit canonicalization
     so that equivalent SMILES written differently still count as a match
   - **Mean best Tanimoto similarity** (RDKit Morgan fingerprints), to give
     partial credit for near-miss structures rather than only pass/fail
4. **Saves results** (`src/pipeline.py`) — writes a per-paper `results.csv`
   and an aggregate `summary.csv` to the output directory.

## Setup

### 1. This repo's dependencies

```bash
python -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. BioMiner itself (separate installation)

BioMiner is not included in this repo - clone and set it up independently
per its own instructions:

```bash
git clone https://github.com/jiaxianyan/BioMiner.git
cd BioMiner
conda env create -f main_environment.yml
conda activate BioMiner
mv magic-pdf.json ~
magic-pdf --version          # confirms MinerU installed correctly
python download_models.py    # downloads MinerU checkpoints

# Also download BioMiner's own model weights (see its README for links):
#   - MolDetV2  -> scripts/moldet_v2_yolo11n_960_doc.pt
#   - MolGlyph  -> scripts/molglyph_large.pt
#   - BioMiner-Instruct -> scripts/local-biominer-instruct
# (Alternatively, configure a closed-source MLLM API key in
#  BioMiner/config/default_open_source.yaml to avoid hosting BioMiner-Instruct
#  locally — this needs only one GPU instead of two.)

# Separate vLLM environment, only needed if using BioMiner-Instruct locally:
conda env create -f vllm_environment.yml
```

Then start BioMiner's background servers (per its README), each in its own
terminal/tmux window:

```bash
conda activate BioMiner
python scripts/mineru_server.py
python scripts/moldet_server.py
python scripts/ocsr_server.py

# Only if using BioMiner-Instruct locally:
conda activate vllm_py310
bash scripts/run_local_vllm_server_biominer_instruct.bash
```

### 3. Dataset

This benchmark uses the course-provided six-paper subset (paper IDs 1, 2, 4,
6, 16, 19), with a ground-truth CSV of 222 confirmed molecule/SMILES pairs
across those papers. **PDFs and the ground-truth CSV are not committed to
this repo** (consistent with BioMiner's own approach to its BioVista
benchmark, which also withholds raw paper PDFs for copyright reasons) —
place your own copies locally:

```
data/
├── pdfs/
│   ├── 1.pdf
│   ├── 2.pdf
│   ├── 4.pdf
│   ├── 6.pdf
│   ├── 16.pdf
│   └── 19.pdf
└── ground_truth_SMILES.csv
```

## Running the benchmark

```bash
python run_benchmark.py \
    --pdf_dir data/pdfs \
    --ground_truth_csv data/ground_truth_SMILES.csv \
    --biominer_repo_path /path/to/BioMiner \
    --output_dir results
```

No paths are hardcoded in the code — every location above is a command-line
argument, so this runs on any machine once the arguments point to valid
local paths.

### Output

- `results/results.csv` - one row per paper, with columns including
  `precision`, `recall`, `f1`, `mean_best_tanimoto`, `true_positives`,
  `false_positives`, `false_negatives`, and `processing_time_sec`
- `results/summary.csv` — the mean of each metric across all papers
- `results/paper_<id>/` — BioMiner's raw output files for that paper,
  preserved for manual inspection

## Status

This pipeline has been verified structurally and against the real dataset,
but **has not yet been run end-to-end against live BioMiner inference**,
since that requires GPU access this environment does not currently have
(BioMiner's model inference step needs a GPU; see "Known limitations" below
for exact requirements).

What has been verified without a GPU:
- `src/data_loader.py` was run directly against the actual six-paper
  dataset and correctly matched all 6 papers to their ground truth,
  reporting 17, 34, 61, 1, 4, and 105 molecules respectively (222 total).
- `src/metrics.py` was tested directly with sample SMILES and correctly
  computes exact-match precision/recall/F1 and Tanimoto similarity via
  RDKit.
- `src/biominer_runner.py` and `src/pipeline.py` are structurally complete
  and call BioMiner's real, documented CLI interface
  (`example_open_source.py`), but have not been executed against a live
  BioMiner installation.

Full end-to-end execution is planned once GPU access (cluster or cloud) is
available.

## Known limitations / notes for the benchmark report (1.3)

- BioMiner's own published performance on its BioVista benchmark (F1 ≈ 0.32
  for full bioactivity triplets; Markush enumeration F1 ≈ 0.70) sets a
  realistic expectation — this is not a solved problem, so a modest score on
  our much smaller six-paper set is expected rather than a sign of a broken
  pipeline.
- This wrapper scores **structure extraction only** (SMILES precision/recall/
  Tanimoto), not BioMiner's full bioactivity-triplet output (protein target,
  measurement type, value, unit) - those fields are outside this course
  assignment's scope but are visible in BioMiner's raw per-paper output for
  anyone who wants to dig deeper.
- Running BioMiner locally with BioMiner-Instruct requires at least two
  A800 80GB-class GPUs per its own documentation; using a closed-source MLLM
  API instead (configured in BioMiner's YAML) reduces this to a single
  consumer GPU, at the cost of depending on an external API.
